# SeaORM 2.0.3

## New Features

* Database-generated columns. A `Model` field can be marked as database-owned with
  `#[sea_orm(generated = "insert" | "update" | "always")]`. Generated columns are
  never written: they are omitted from `INSERT` and `UPDATE`, and their value is
  fetched back from the database afterwards (`RETURNING` where supported, an extra
  `SELECT` otherwise). This supports both database-first mapping of an existing
  generated column and entity-first schema generation.
* Schema-generation attributes for generated columns, kept deliberately separate
  from the ORM lifecycle metadata:
  * `generated_expression = "expr"` emits the portable
    `GENERATED ALWAYS AS (expr) STORED` form (PostgreSQL, MySQL, MariaDB, SQLite);
    `generated_stored = false` emits `VIRTUAL` instead.
  * `column_definition = "..."` appends raw, database-specific column DDL verbatim,
    the escape hatch equivalent to Hibernate's `columnDefinition` (for example a
    SQL Server computed column). SeaORM does not parse the string.
* `ColumnDef` gains `GeneratedColumn` metadata and `is_generated` /
  `generated_on_insert` / `generated_on_update` accessors, and `ColumnTrait` gains
  the matching helper methods.
* `DeriveEntityModel` rejects invalid combinations at compile time: an unknown
  `generated` value, `generated` together with `default_value` / `default_expr`,
  a generated auto-incremented primary key, and `generated_stored` without
  `generated_expression`.

## Limitations

* Database-generated columns are omitted from `INSERT` and `UPDATE` for every
  `generated` value. The `"insert"` / `"update"` / `"always"` distinction records
  when the database (re)computes the value.
* A single `insert` / `update` refreshes the generated values on the returned
  model (`RETURNING` where supported, otherwise a follow-up `SELECT`).
  `insert_many` does not report per-row generated values; read the rows back
  explicitly if needed. `update_many` returns only the number of affected rows.
* Upserts use the same insert path, so generated columns are never inserted;
  whether the database recomputes them on the conflict path is up to the
  database and the expression. Do not add generated columns to
  `OnConflict::update_columns`.
* `generated_expression` emits the `GENERATED ALWAYS AS (...) STORED|VIRTUAL`
  syntax shared by PostgreSQL, MySQL, MariaDB and SQLite. SQL Server is not a
  supported backend in this version; its computed-column syntax
  (`AS (...)`) can still be expressed with `column_definition`.
* Database-first schema reflection (for example `sea-orm-cli generate entity`)
  does not yet detect generated columns; add the `generated` attribute manually
  when mapping an existing generated column.
